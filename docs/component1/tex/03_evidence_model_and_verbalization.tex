\subsection{Verbalizer versioning}
\texttt{VERBALIZER\_VERSION = "v3"} is part of the cache key and log metadata.
Any change to verbalization logic must update this identifier to prevent stale cache reuse.

\subsection{Deterministic text normalization helpers}
\texttt{normalize\_relation(rel)} performs:
\begin{enumerate}
\item URI prefix stripping (\texttt{http://}, \texttt{https://}),
\item URI tail extraction after \texttt{/} or \texttt{\#},
\item camelCase splitting (e.g., \texttt{birthPlace} $\rightarrow$ \texttt{birth place}),
\item underscore and hyphen replacement by spaces,
\item lowercasing and whitespace collapse.
\end{enumerate}

\texttt{extract\_entity\_name(entity)} performs:
\begin{enumerate}
\item quote stripping for literals,
\item URI tail extraction,
\item underscore replacement by spaces.
\end{enumerate}

\subsection{Triple-to-premise conversion}
For \texttt{kg\_triple} evidence, \texttt{evidence\_to\_text} uses template:
\begin{equation}
\text{premise}(e) = \texttt{"\{subject\} has \{relation\} \{object\}."}
\end{equation}

Inverse relations are handled explicitly:
\begin{equation}
(s,\;\texttt{\textasciitilde r},\;o) \Rightarrow (o,\;r,\;s)
\end{equation}
before template rendering.

\subsection{Hashing contract for deterministic identity}
\texttt{stable\_hash(text)} uses full SHA-256 and returns a 64-character hex string.
This is used for:
\begin{itemize}
\item claim keys (hash of claim text),
\item evidence hash (hash of verbalized premise),
\item persistent cache lookup keys.
\end{itemize}

\subsection{Important caveat for graph metrics}
Coverage/connectivity metrics use raw triple subject/object strings as graph nodes.
Therefore claim entity strings must be compatible with the same identifier style
(e.g., DBpedia tail strings with underscores) for faithful overlap computation.
